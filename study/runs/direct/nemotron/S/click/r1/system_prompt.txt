What the tables and columns mean:
code.snapshot: One row identifying the analysed source: repository, commit, content fingerprint, builder and its known limits. Primary key: snapshot_id.
  snapshot_id (VARCHAR): Stable id of this snapshot: commit prefix and fingerprint prefix.
  repo_url (VARCHAR): URL of the analysed repository.
  commit_sha (VARCHAR): Commit SHA of the analysed checkout.
  built_at (VARCHAR): UTC time the map was built, ISO 8601 (SOURCE_DATE_EPOCH when set).
  builder_version (VARCHAR): Name and version of the builder that produced the rows.
  source_fingerprint (VARCHAR): 16-hex SHA-256 digest over sorted 'path NUL file-sha256' lines of every analysed file.
  file_count (INTEGER): Number of Python files analysed.
  omitted_file_count (INTEGER): Number of Python files found but not analysed (excluded or unparseable).
  known_limits (VARCHAR): JSON array of plain-language limits of the static analysis.

code.files: One row per analysed Python source file. Module and package descriptions are in files.description; a package description belongs to its __init__.py row. Primary key: file_id.
  file_id (VARCHAR): Repository-relative path of the file, with forward slashes.
  package (VARCHAR): Dotted name of the package that contains the module; empty for a top-level module.
  module (VARCHAR): Dotted import name of the module (a package's __init__.py has the package's name).
  is_test (BOOLEAN): True when the path or file name marks the file as a test (tests/ or test/ directory, test_*.py, *_test.py, conftest.py).
  line_count (INTEGER): Number of lines in the file.
  sha256 (VARCHAR): SHA-256 of the file's bytes; used to detect stale certifications.
  description (VARCHAR): Verbatim description from the module docstring; empty when the file has none.
  description_source (VARCHAR): Where the description came from: heading_purpose, module_docstring or none.
  has_fixed_headings (BOOLEAN): True when the module docstring uses the fixed headings [PURPOSE], [INTERFACE], [FLOW], [DEPENDENCIES] or [CONSTRAINTS].

code.headings: Optional fixed sections and contract atoms from module docstrings only. This table can be empty even when ordinary module and function docstrings exist. Function docstrings are in symbols.summary, not this table. Primary key: file_id, ordinal.
  file_id (VARCHAR): File whose module docstring holds the heading.
  heading (VARCHAR): Heading name such as [PURPOSE], or an atom name such as Teleology or Fails.
  value (VARCHAR): Verbatim text under the heading or after the atom.
  ordinal (INTEGER): Position of the heading within the file's docstring, from 1.

code.symbols: Functions, methods and classes, their definition locations and extracted docstring summaries. Use this table for function definitions and function docstring questions. Primary key: symbol_id.
  symbol_id (VARCHAR): ID: file path, '::', qualified name; repeated qualified definitions append @L<definition-line>.
  file_id (VARCHAR): File that defines the symbol.
  name (VARCHAR): Bare name of the symbol.
  qualname (VARCHAR): Dotted name within the module, e.g. Class.method.
  kind (VARCHAR): function, method or class.
  line_start (INTEGER): First line of the definition, decorators excluded.
  line_end (INTEGER): Last line of the definition.
  is_public (BOOLEAN): True when neither the name nor any enclosing class name starts with an underscore.
  summary (VARCHAR): First paragraph (or Teleology atom) of this function, method or class docstring, with whitespace normalized; empty when absent. This is the function documentation, unlike optional module headings.
  summary_source (VARCHAR): docstring or none.

code.class_bases: Base classes named in each class statement, in order, with the internal class each one resolves to. Primary key: class_symbol_id, ordinal.
  class_symbol_id (VARCHAR): Class whose statement names the base.
  ordinal (INTEGER): Position of the base in the class statement, from 1.
  base_name (VARCHAR): Base expression as written, e.g. SQLDatabase, base.SQLDatabase or Generic[T].
  base_symbol_id (VARCHAR): Internal class the base resolves to by the same static rules as calls; null for external, builtin or unresolvable bases.

code.calls: Call edges inside functions, methods and class bodies, with how the callee was resolved. Direct call sites are all kept; those without an internal callee have a null callee and are classified as builtin, external, dynamic_attribute or unresolved. Callback rows record an internal function or method passed by reference as an argument to another call, e.g. asyncio.to_thread(f, x). Primary key: call_id.
  call_id (VARCHAR): Stable id: file path, line, column and a sequence number (for a callback row, the position of the argument).
  caller_symbol_id (VARCHAR): Symbol whose body contains the call.
  callee_symbol_id (VARCHAR): Internal callee symbol; set only for same_file, imported and method_on_self, null otherwise.
  callee_name (VARCHAR): Callee as written at the call site, e.g. self.save or pd.read_csv; for a callback row, the reference as written in the argument.
  line (INTEGER): Line of the call.
  resolution (VARCHAR): same_file, imported or method_on_self (internal callee found); builtin (a Python builtin such as len); external (rooted in a third-party or standard-library import, or a module-level name assigned from one, e.g. logger); dynamic_attribute (a method on an object whose type is not statically known, e.g. row.get); unresolved (anything else).
  confidence (VARCHAR): high or low: low for inherited methods, callback rows, dynamic_attribute and unresolved.
  call_kind (VARCHAR): direct (the call site invokes the callee) or callback (an internal function or method passed as an argument, e.g. asyncio.to_thread(f, x), executor.submit(f) or Thread(target=f), which the receiving call is expected to invoke). Callback rows always carry a callee and low confidence.

code.imports: Import statements, one row per imported name, with the internal file each resolves to. Primary key: import_id.
  import_id (VARCHAR): Stable id: file path, line and a sequence number.
  file_id (VARCHAR): File containing the import.
  imported_file_id (VARCHAR): Internal file the import resolves to; null for external or unresolvable imports.
  module_name (VARCHAR): Absolute dotted module name imported (relative imports resolved).
  line (INTEGER): Line of the import statement.
  is_internal (BOOLEAN): True when the module belongs to the analysed repository.

code.test_links: Static associations between a test file and a source file, inferred because the test imports the file or its name matches. They are not measured test execution or coverage. Primary key: test_file_id, target_file_id, reason.
  test_file_id (VARCHAR): Test file.
  target_file_id (VARCHAR): Non-test file the test is linked to.
  reason (VARCHAR): imports_target (the test imports the file) or name_match (test_<name>.py matches <name>.py).

code.inbound_call_counts: Every symbol with the number of resolved direct call sites that target it, the number of callback references to it, and the number of distinct callers of either kind.
  symbol_id (VARCHAR): ID: file path, '::', qualified name; repeated qualified definitions append @L<definition-line>.
  file_id (VARCHAR): File that defines the symbol.
  name (VARCHAR): Bare name of the symbol.
  qualname (VARCHAR): Dotted name within the module, e.g. Class.method.
  kind (VARCHAR): function, method or class.
  is_public (BOOLEAN): True when neither the name nor any enclosing class name starts with an underscore.
  inbound_calls (HUGEINT): Number of resolved direct call sites whose callee is this symbol.
  callback_references (HUGEINT): Number of places where this symbol is passed by reference as an argument to another call.
  distinct_callers (BIGINT): Number of distinct symbols that call this symbol directly or pass it as a callback.

code.untested_public_symbols: Public symbols in non-test files whose file has no recorded test association (no test imports it or matches its name). This does not show that the symbol is never tested.
  symbol_id (VARCHAR): ID: file path, '::', qualified name; repeated qualified definitions append @L<definition-line>.
  file_id (VARCHAR): File that defines the symbol.
  name (VARCHAR): Bare name of the symbol.
  qualname (VARCHAR): Dotted name within the module, e.g. Class.method.
  kind (VARCHAR): function, method or class.

Code semantics layer (views over the base tables; prefer them where they fit):

code.call_edges: One row per ordered pair of internal symbols where the first calls or references the second, aggregating every call site between them. Use calls_directly for 'calls' or 'direct callers'; a pair can exist only because the caller passes the callee as a callback (calls_directly false). Only resolved internal callees appear; calls to builtins, third-party code and unresolved names are not edges. Key: caller_symbol_id, callee_symbol_id.
  caller_symbol_id: Symbol whose body contains the call sites or callback references.
  callee_symbol_id: Internal symbol called or referenced.
  direct_call_sites: Number of call sites where the caller invokes the callee directly.
  callback_references: Number of places where the caller passes the callee as an argument, e.g. asyncio.to_thread(f).
  calls_directly: True when the caller invokes the callee directly at least once. This is the meaning of 'X calls Y' and 'direct caller'.
  passes_as_callback: True when the caller passes the callee as a callback reference at least once.
  first_line: Smallest line number among the call sites and references in the caller's file.
  is_self_call: True when the symbol calls or references itself.
  caller_kind: function, method or class: kind of the caller (a class appears when the call is in its class body).
  caller_file_id: File that defines the caller.
  caller_in_test_file: True when the caller is defined in a test file.
  callee_kind: function, method or class: kind of the callee. Calling a class constructs an instance.
  callee_file_id: File that defines the callee.
  callee_in_test_file: True when the callee is defined in a test file.
  Joins: caller_symbol_id -> code.symbols.symbol_id; callee_symbol_id -> code.symbols.symbol_id; caller_file_id -> code.files.file_id; callee_file_id -> code.files.file_id

code.reachability: Transitive callers: one row per pair (caller, target) where a chain of call edges leads from the caller to the target, with the length of the shortest chain. direct_depth follows direct calls only and is null when the target is reachable only through a callback reference; any_depth also follows callback references. The chain length is unbounded and cycles are handled. A symbol is never listed as reaching itself. Use this view for 'directly or indirectly', 'transitively', 'can reach', 'impact of changing' and shortest-depth questions instead of writing a recursive query. Key: caller_symbol_id, target_symbol_id.
  caller_symbol_id: Symbol from which a chain of calls reaches the target.
  target_symbol_id: Symbol reached.
  direct_depth: Edges in the shortest chain of direct calls from caller to target (1 = calls it directly); null when every chain needs a callback reference.
  any_depth: Edges in the shortest chain when callback references also count as edges; never larger than direct_depth.
  caller_kind: function, method or class: kind of the caller.
  caller_file_id: File that defines the caller.
  caller_in_test_file: True when the caller is defined in a test file.
  Joins: caller_symbol_id -> code.symbols.symbol_id; target_symbol_id -> code.symbols.symbol_id; caller_file_id -> code.files.file_id

code.symbol_profile: One row per function, method and class with the facts most questions filter on: kind flags, visibility, test location, docstring presence, size, enclosing class and inbound and outbound call counts. 'Function' means kind = 'function' (module-level def); methods are defs inside a class; classes are not functions even though calling one constructs an instance. Key: symbol_id.
  symbol_id: Symbol ID, as in code.symbols.
  file_id: File that defines the symbol.
  name: Bare name.
  qualname: Dotted name within the module, e.g. Class.method.
  kind: function, method or class.
  is_function: True for module-level functions (kind = 'function').
  is_method: True for functions defined in a class body.
  is_class: True for classes.
  is_public: True when neither the name nor any enclosing class name starts with an underscore.
  is_dunder: True for names of the form __name__, e.g. __init__.
  in_test_file: True when the defining file is a test file.
  module: Dotted module name of the defining file.
  enclosing_class_symbol_id: For a method, the class that defines it; null otherwise.
  line_start: First line of the definition, decorators excluded.
  line_end: Last line of the definition.
  line_span: line_end - line_start + 1.
  has_docstring: True when the symbol has a docstring (summary_source = 'docstring').
  direct_callers: Distinct other symbols that call this one directly.
  callers_any_kind: Distinct other symbols that call it directly or pass it as a callback.
  inbound_direct_call_sites: Direct call sites, in all callers, that resolve to this symbol.
  inbound_callback_references: Places where this symbol is passed as a callback.
  internal_callees: Distinct other internal symbols this one calls directly.
  outgoing_call_sites: Direct call sites in this symbol's body, including calls to builtins and external code.
  Joins: symbol_id -> code.symbols.symbol_id; file_id -> code.files.file_id; enclosing_class_symbol_id -> code.symbols.symbol_id

code.file_profile: One row per Python file with its directory, top-level package, documentation, size, definition counts, internal import counts and static test links. directory is the folder that contains the file ('' at the repository root); group by directory, not by module or package, for questions about folders. Key: file_id.
  file_id: Repository-relative path.
  module: Dotted import name.
  package: Dotted package name; empty for a top-level module.
  directory: Folder containing the file, as a path without trailing slash; '' at the repository root.
  top_directory: First path component for files in a folder; '' at the repository root.
  file_name: Last path component, e.g. server.py.
  is_test: True for test files.
  is_package_init: True for __init__.py files.
  line_count: Number of lines in the file.
  has_module_docstring: True when the file has a module docstring (files.description_source is not 'none').
  function_count: Module-level functions defined in the file.
  method_count: Methods defined in the file's classes.
  class_count: Classes defined in the file.
  public_symbol_count: Public functions, methods and classes in the file.
  imports_internal_files: Distinct other repository files this file imports.
  imported_by_files: Distinct other repository files that import this file.
  linked_test_files: Distinct test files statically linked to this file (imports or name match); not coverage.
  Joins: file_id -> code.files.file_id

code.file_dependencies: Internal module dependencies: one row per ordered pair of distinct repository files where the first imports the second. Imports of external modules are excluded. Key: importer_file_id, imported_file_id.
  importer_file_id: File containing the import statements.
  imported_file_id: Repository file it imports.
  imported_names: Import rows (one per imported name) between the two files.
  first_line: Line of the first import of that file.
  importer_is_test: True when the importing file is a test file.
  Joins: importer_file_id -> code.files.file_id; imported_file_id -> code.files.file_id

code.class_ancestry: Transitive inheritance among internal classes: one row per (class, ancestor) with the number of inheritance steps (1 = a direct base). Only bases that resolve to classes in the repository are followed; external bases such as Exception or BaseModel are in code.class_bases.base_name. Key: class_symbol_id, ancestor_symbol_id.
  class_symbol_id: Class.
  ancestor_symbol_id: Internal class it inherits from, directly or through other internal classes.
  depth: Inheritance steps on the shortest path; 1 for a direct base.
  Joins: class_symbol_id -> code.symbols.symbol_id; ancestor_symbol_id -> code.symbols.symbol_id

Definitions:
  calls / direct caller: A calls B when a call site in A's body invokes B: code.call_edges with calls_directly. Passing B as an argument (a callback reference) is not a call.
  callback reference: A passes B by name as an argument to another call, e.g. asyncio.to_thread(B) or Thread(target=B): code.call_edges with passes_as_callback. The receiving call is expected to run B, but this is a static reference, not an observed execution.
  reaches / transitive or indirect caller: A chain of call edges leads from A to B: code.reachability. Use direct_depth for chains of direct calls only, any_depth when callback references count.
  function, method, class: A function is a module-level def (kind = 'function'); a method is a def in a class body; a class is neither, although calling a class constructs an instance and appears as a call to the class.
  public: is_public: neither the name nor an enclosing class name starts with an underscore. Dunder methods such as __init__ are therefore not public.
  test code: Anything defined in a file with is_test true. 'Outside tests' means in_test_file / caller_in_test_file false.
  documented: A symbol has a docstring when has_docstring is true; a file has a module docstring when has_module_docstring is true. Docstring text is in code.symbols.summary and code.files.description.
  directory, package, module: directory is the folder path of the file (code.file_profile.directory); package and module are dotted import names and differ from the folder for top-level scripts.
  tested: code.test_links records static associations (a test file imports the file or matches its name). It is not coverage; say 'linked to a test', not 'covered'.
  depends on / imports: File A depends on file B when A imports B: code.file_dependencies. External imports are in code.imports with is_internal false.
